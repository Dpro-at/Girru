## Unfinished: the Memory Ranking experiment

**Read `docs/internal/RANKING_FINDINGS.md` first.** It is the analysis, done before any change.

What it found, on two real projects, by replaying exactly what `docRecall` scores and then each cutoff:

| 40 heading queries | This repository | Flowxtra |
|---|---|---|
| Returned | 26 | 19 |
| **Cut by `MAX_PER_FILE = 2`** | **7** | **8** |
| Cut by the limit of 4 | 1 | 1 |
| Genuinely ranked low | 6 | 12 |
| Below the score floor | 0 | 0 |
| Target's rank in the full list, p50 | **2 of 3,392** | **4 of 8,000** |
| p90 | 9 | 137 |

**The scoring is mostly not the problem.** The median right passage already ranks second. The biggest
single cause of a miss is the per-file cap taking its slot. Most "misses" are not misses of the topic
either: in 12 of 14 and 16 of 21 a passage under the *same heading* was in the best four.

### The change that exists but is NOT proven

Branch **`girru/ranking-file-cap-wip`**, commit `bc715ff4`. **Do not merge it on current evidence.**
It lets the per-file cap yield a slot that would otherwise go empty. On this repository: same-heading
in the best four 85% → 88%, exact passage 68% → 73%, latency unchanged. **Flowxtra could not be
compared.**

### The measurement bug that blocks it — fix this first

Between two runs with identical settings, the share of repeated headings in the Flowxtra sample moved
from **45% to 60%**. Same N, same command. That can only mean **the sample changed**: the document
index stops at 500 files and took in a different 500. So the Flowxtra before/after are different
questions and prove nothing.

To fix: make `--known-item` pick a stable sample (order by file path and ordinal, not by chunk id,
which is a hash) and make the 500-file cap deterministic. Then re-measure both projects.

## Known issues, not fixed

1. **The setup dead end.** The owner hit "Open setup on this computer" during registration inside the
   Girru window, with only a Back button. It is **not a stray page to delete**: the setup code is the
   control that stops anyone but the person at the installation computer creating the owner, and
   removing the page only moves the failure to the server (`setup_token_missing`).
   The likely cause is in `packages/core-ui/src/AuthBoundary.tsx`: `readSetupLink()` reads `#setup=…`
   once per page load and **immediately strips it from the URL**, keeping it only in memory, so a
   reload or reopened window loses it. Not confirmed — there is no installed Girru data folder on this
   machine to inspect, and the owner has not yet said whether it followed a reload or a fresh install.
   Ask before fixing.
2. **PostgreSQL has no change capture at all** and its search uses the older in-process path. The owner
   deprioritised it on 13 November.
3. **Bulk writes are slower with the change log**: seeding 100,000 memories went 11.6 s → 17.3 s, one
   log row per write. Rows are pruned after an hour.
4. **Known Windows-only test failures**, unchanged and not regressions: POSIX file modes (0666 vs
   0600) in `memory-bridge`, and `EPERM` when a test removes its temp folder while SQLite still holds
   the file.

## Tests and tools, and what each is for

| Tool | What it answers |
|---|---|
| `scripts/memory-baseline/agents.mjs` | several agents in their own processes on one SQLite file: reads together, reads while another saves, three edits of one memory, handoff travel, project isolation |
| `scripts/memory-baseline/real-project.mjs` | Girru reading a real project's own documents; `--known-item N` asks real headings so nobody writes the questions; `--repo <path>`, `--vectors hash` |
| `scripts/memory-baseline/bridge-e2e.mjs` | the real MCP server, one OS process per tool, four tools on one memory — 15 of 15 |
| `scripts/memory-baseline/save-profile.mjs` | where one save spends its time at a given size |
| `scripts/memory-baseline/accuracy.mjs` | the generated accuracy world; `--held-out` is a second question set no threshold was chosen on; `--pack` writes what a chat would send a model |
| `pack-score.mjs`, `pack-diff.mjs` | score any model's answers to a pack, and find the questions where a change altered recall |

**Two levels, always measured apart** (the owner's rule): Girru's own score is retrieval; what a model
then answers is a second, separate number. A weak local model failing is not a memory failure — proved
on 13 November, when a retrieval gain read as neutral through `qwen2.5:7b` and as 8/14 → 14/14 correct
through a strong model.
